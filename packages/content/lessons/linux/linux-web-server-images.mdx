Some images ship with Apache and PHP running, and the README requires the
site to stay reachable. This is the hardest shape of Linux hardening,
because the usual instinct — find the exposed service, turn it off — is
exactly the wrong move and carries a penalty.

Required means the service keeps serving. It does not mean the service keeps
its current configuration.

## Do not drop privileges by stopping the service

Check what Apache is running as:

```
ps aux | grep apache2
```

The parent process runs as root because it must bind port 80. The **worker**
processes should not. On Ubuntu they should be `www-data`, set in
`/etc/apache2/apache2.conf`:

```
User www-data
Group www-data
```

If workers are running as root, a flaw in any hosted application becomes a
root compromise rather than a `www-data` one. Fixing this keeps the site up
and removes most of the risk.

## Stop advertising the version

```
ServerTokens Prod
ServerSignature Off
```

By default Apache announces its exact version, and often the OS, in response
headers and on generated error pages. That tells an attacker precisely which
known vulnerabilities to try. On Ubuntu these usually belong in
`/etc/apache2/conf-available/security.conf`.

## Turn off directory listings

```
<Directory /var/www/html>
    Options -Indexes
</Directory>
```

Without this, a directory with no index file is served as a browsable list.
That is how backup files, `.sql` dumps and editor swap files end up public —
nobody linked them, but nobody had to.

## File ownership under the web root

```
sudo find /var/www -type f -exec chmod 644 {} \;
sudo find /var/www -type d -exec chmod 755 {} \;
```

Files readable, directories traversable, neither writable by the world. A
world-writable file under the web root means anyone who can write to it can
change what the site serves.

Be specific about ownership: the web server needs to **read** its content.
It rarely needs to **write** it. A document root owned entirely by
`www-data` with write permission is more access than most sites require.

## PHP settings worth checking

In `/etc/php/*/apache2/php.ini`:

```
display_errors = Off
expose_php = Off
```

`display_errors` on a production site prints file paths, query fragments and
sometimes credentials straight to the browser when something breaks.
`expose_php` adds the PHP version to response headers — the same
version-disclosure problem as `ServerTokens`.

## Apply changes safely

Apache has the same test-before-restart discipline as SSH:

```
sudo apache2ctl configtest && sudo systemctl restart apache2
```

`configtest` parses the configuration and reports errors. If it fails, the
restart does not happen and the site stays up on the old config. Restarting
a required service into a broken config takes the site down, which is the
penalty you were trying to avoid in the first place.
