Permission findings are quiet. Nothing breaks, nothing looks wrong on the
surface, and the scoring engine notices immediately. These are among the
fastest points on a Linux image once you know exactly what to look at.

## The three files with fixed correct answers

```
/etc/shadow    640
/etc/passwd    644
/etc/sudoers   440
```

`/etc/shadow` holds password hashes and must not be world-readable. A
world-readable shadow file is a scored finding on essentially every image
that plants it, because it hands every local user the material for an
offline cracking attempt.

`/etc/passwd` is deliberately world-readable — it holds no secrets, and
ordinary commands need it to map UIDs to names. Do not "harden" it to 600;
you will break things and score nothing.

`/etc/sudoers` at 440 is read-only even for root. That is intentional: it
makes an accidental edit take a deliberate extra step.

To check and fix:

```
ls -l /etc/shadow /etc/passwd /etc/sudoers
sudo chmod 640 /etc/shadow
sudo chmod 440 /etc/sudoers
```

## SUID binaries

A SUID binary runs with its **owner's** privileges, not the privileges of
whoever executed it. When the owner is root, any user who can run it can
take a root-level action. That is why a planted SUID binary is a complete
privilege-escalation path in one file.

```
sudo find / -perm -4000 -type f 2>/dev/null
```

The `2>/dev/null` discards permission-denied noise from directories you
cannot read, which otherwise buries the results.

A normal system returns a familiar list — `sudo`, `su`, `passwd`, `mount`,
`ping` and a handful of others. What you are hunting is the entry that does
not belong: a copy of `bash`, `find`, `vim`, `nmap` or `python` with the
SUID bit set. Any of those with SUID is an immediate root shell for any
user.

```
sudo chmod u-s /path/to/binary
```

Compare against a known-good list rather than trusting your memory, and be
careful not to strip SUID from something legitimate — `sudo` and `passwd`
genuinely need it.

## World-writable directories and the sticky bit

```
sudo find / -type d -perm -0002 -not -path "/proc/*" 2>/dev/null
```

A world-writable directory lets any user drop files in — which combines
badly with anything that later executes what it finds there.

`/tmp` is the deliberate exception. It has to be world-writable to do its
job, and the sticky bit is what makes that safe:

```
ls -ld /tmp        # expect drwxrwxrwt
sudo chmod 1777 /tmp
```

The trailing `t` is the sticky bit. With it, a user can create files in
`/tmp` but can only delete or rename their own. Without it, any user can
delete anyone's files there — including replacing a file another process is
about to read.
