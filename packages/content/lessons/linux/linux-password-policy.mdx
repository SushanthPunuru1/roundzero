Password hardening on Linux is not one setting. It is quality rules, reuse
history, lockout behaviour, and expiry — four mechanisms in four places, all
usually scored separately. Setting one and assuming you are done is the most
common way to leave points on the table.

## Quality — how strong a new password must be

Rules live in `/etc/security/pwquality.conf`, provided by the
`libpam-pwquality` package. If the package is not installed, the file may not
exist and nothing is enforcing anything.

```
sudo apt install libpam-pwquality
```

The settings that matter:

```
minlen = 14
dcredit = -1
ucredit = -1
ocredit = -1
lcredit = -1
```

`minlen` is the minimum length. The four `*credit` values cover digits,
uppercase, others (symbols) and lowercase. A **negative** number means
"require at least this many of that class." A positive number means
something quite different — it gives credit toward the length requirement,
which weakens the policy rather than strengthening it. Negative is what you
want.

## History — stopping password reuse

Quality rules do nothing if a user cycles back to their old password. That
is `pam_pwhistory`, configured in `/etc/pam.d/common-password`:

```
password required pam_pwhistory.so remember=5 use_authtok
```

`remember=5` blocks the last five passwords. Some images place this
elsewhere or omit it entirely — check the file before assuming.

## Lockout — surviving a guessing attack

Modern Ubuntu uses `pam_faillock`, configured in
`/etc/security/faillock.conf`:

```
deny = 5
fail_interval = 900
unlock_time = 1800
```

That is five failed attempts within fifteen minutes, locking for thirty.

The trap: `pam_faillock` **replaced** `pam_tally2`. Guides written a few
years ago still say `pam_tally2`, and configuring it on a current image
accomplishes nothing at all — the module is not loaded, so nothing reads
your settings. If you see `pam_tally2` referenced anywhere, you are reading
stale instructions.

## Aging — how long a password stays valid

Defaults for newly set passwords live in `/etc/login.defs`:

```
PASS_MAX_DAYS   90
PASS_MIN_DAYS   7
PASS_WARN_AGE   14
```

These apply going forward. Accounts that already exist keep whatever they
have, so you must set them individually:

```
sudo chage -M 90 -m 7 -W 14 username
```

Max age 90, min age 7, warning 14. To see what an account currently has:

```
sudo chage -l username
```

Do this for every human account in the README. A policy set only in
`login.defs` on a box full of pre-existing users scores nothing.
