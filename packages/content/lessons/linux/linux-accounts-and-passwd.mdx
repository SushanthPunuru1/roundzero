Linux does not have one list of users — it has two files that work together,
and knowing which one answers which question is most of this skill. This
lesson is about reading them fast enough to spot the account that should not
be there.

## The two files

`/etc/passwd` is the account list: name, UID, group, home directory, shell.
It is world-readable, which surprises people, but it holds no passwords.

`/etc/shadow` is the password file: the hash, and the aging rules attached
to it. It is readable only by root, which is why nearly every command here
starts with `sudo`.

A user exists because there is a line in `/etc/passwd`. Whether they can log
in, and how, is answered by `/etc/shadow`.

## Reading the account list

The field order in `/etc/passwd` is fixed and colon-separated:

```
username:x:UID:GID:comment:home:shell
```

Field 3 is the UID, and it is the field that matters. Accounts below 1000
are system accounts created by packages. Real people start at 1000. The
account `nobody` sits at 65534.

```
awk -F: '$3>=1000 && $3<65534 {print $1}' /etc/passwd
```

That is your list of humans. Compare it against the README, line by line.
Anyone on the machine but not in the README is unauthorized; anyone in the
README but not on the machine may need creating.

## UID 0 is the one that matters

Linux decides who is root by UID, not by username. An account named
`backupsvc` with UID 0 is root with a boring name.

```
awk -F: '$3==0 {print $1}' /etc/passwd    # should print only: root
```

If that prints anything besides `root`, you have found a scored item. Do not
change the UID and move on — read the README first, because the fix is
usually removing the account, not renaming it.

## Blank and weak passwords

An account with an empty password field authenticates with nothing at all:

```
sudo awk -F: '($2==""){print $1}' /etc/shadow
```

The second field is the hash. Empty means no password. A `!` or `*` there
means the account is locked, which is normal and correct for system
accounts like `daemon` or `sys` — do not "fix" those.

## The trap worth remembering

A suspicious-sounding username is not evidence. An account called
`hackerman` that appears in the README is authorized, and removing it costs
you points. An account called `svc-backup` that does not appear in the
README is not authorized, however plausible it sounds. The README is the
authority, every time.
