PowerShell is to Windows what bash is to Linux, and the same discipline
applies: read everything before you change anything. These queries only
report, so run them the moment you sit down.

## The naming pattern

PowerShell commands are `Verb-Noun`. Once you know that, most of them are
guessable:

```
Get-LocalUser
Get-Service
Get-Process
Get-LocalGroupMember
```

`Get-` reads. `Set-`, `Stop-`, `Remove-` and `Disable-` change things — which
is a useful safety rule: if the command doesn't start with `Get-`, think
before you press enter.

## Accounts

```
Get-LocalUser
Get-LocalUser | Where-Object {$_.Enabled -eq $true}
Get-LocalGroupMember Administrators
```

The first lists every local account with its enabled state. The second narrows
to accounts that can actually log in. The third is the one that matters most —
compare it against the README's authorized administrators, and anyone extra is
a finding.

```
net user
net localgroup administrators
```

The older `net` commands do the same job and are worth knowing, because they
work in `cmd` when PowerShell is restricted.

## Services

```
Get-Service | Where-Object {$_.Status -eq "Running"} | Sort-Object Name
Get-Service -Name Telnet, FTPSVC, SNMP
```

The pipeline here is the thing to understand. `Get-Service` emits service
*objects*, `Where-Object` filters them on a real property, and `$_` refers to
whichever object is passing through. Because it filters on properties rather
than text, it doesn't break when output formatting changes — a genuine
advantage over parsing strings.

## The registry

The registry is browsable like a filesystem:

```
Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" -Name AutoAdminLogon
```

The `Run` key is a classic persistence location — anything listed there
launches at login, and unfamiliar entries are worth reading closely.

## Network and scheduled tasks

```
netstat -ano | findstr LISTENING
Get-ScheduledTask | Where-Object {$_.State -ne "Disabled"}
```

Scheduled tasks are the Windows equivalent of cron, and the same persistence
hiding place.

## Policy

```
net accounts
secedit /export /cfg C:\policy.txt
```

`net accounts` shows password age, length and lockout settings. Note that it
can display complexity but cannot set it — a trap worth remembering, since
setting complexity requires Local Security Policy or `secedit`.

## Saving output

```
Get-LocalUser | Out-File C:\audit-users.txt
Get-Service | Export-Csv C:\audit-services.csv
```

Same reasoning as on Linux: a saved snapshot lets you diff against a later one
and see what changed while you worked.
